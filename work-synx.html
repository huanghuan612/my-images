The Challenge

技术很多，但客户不一定看得懂

数据库产品涉及性能、迁移、兼容性、架构等多个复杂维度。每个技术点都有价值，但如果同时抛给用户，只会造成信息过载。

真正的问题不是"讲什么"，而是"先讲什么"。用户才愿意继续看下去。

核心设计问题：如何组织信息优先级，让用户从"理解价值"自然过渡到"验证技术"？

Design Principle

先讲价值，再讲技术

我把核心体验组织成一条渐进式路径。用户不需要一开始就理解所有技术细节，而是先判断"这个产品是否值得我了解"。

01

Value first, details later

首页先回答"为什么选 SYNX"，而不是堆砌技术参数。

02

One page, one purpose

每个页面只解决一个问题，不试图在单页内完成所有说服。

03

Professional but approachable

专业感建立信任，但克制的设计让复杂技术不显得 intimidating。

04

Trust through transparency

技术文档、团队背景、开源贡献，让信任有具体支撑。

我的角色

UX / Web Design

  • 信息架构规划，定义 Understand → Verify → Trust → Contact 路径
  • 首页设计，梳理"Why SYNX"的价值层级
  • 多页面体系设计：Home / Docs / About / Blog
  • 视觉系统设计，建立深蓝科技感的品牌调性
  • 响应式设计与前端交付

先回答"为什么是 SYNX"

首页先讲产品价值和企业能力，再逐步进入技术细节。先让用户判断值不值得继续了解。

synxdata.com

设计决策

首页采用"价值金字塔"结构：Hero 区域用一句话定位产品（Seamless Greenplum Migration），紧接着"Why SynxDB?"用 4 张卡片概括核心优势，再往下才是技术架构细节。用户可以在任意层级停止阅读，已经获得了足够的信息。

关键特性

  • Hero 区一句话价值主张 + CTA
  • "Why SynxDB?" 四宫格价值卡片
  • Enterprise Ready 功能矩阵
  • 技术架构可视化展示
  • Contact 表单降低沟通门槛

不同页面，解决不同问题

Home 理解产品 · Docs 验证技术 · About 建立信任 · Blog 持续输出专业内容。

synxdata.com/about

Blog — 持续输出

设计决策

每个页面有明确的单一目标。Docs 采用技术文档的标准三栏布局（导航+内容+目录），降低技术用户的学习成本。About 用团队照片和背景故事建立人情味信任。Blog 用卡片式布局展示专业内容，同时保持视觉节奏。

关键特性

  • Docs：三栏文档结构，左侧导航、中间内容、右侧目录锚点
  • About：团队照片+背景故事，让技术公司有人情味
  • Blog：卡片式文章列表，封面图+摘要+作者信息
  • 全局导航统一，深色主题保持品牌一致性

专业、稳定、可信

深蓝主色、统一栅格、克制的科技感，让复杂技术内容更有秩序。

设计决策

面向海外企业客户，视觉系统需要在"专业可信"和"现代 approachable"之间找到平衡。过重的科技感会让人觉得复杂难懂，过轻又缺乏 enterprise 应有的稳重感。

关键特性

  • 深色主题贯穿全站，降低长时间阅读疲劳
  • 蓝色渐变光效营造科技感但不浮夸
  • 统一 8px 栅格系统，保持页面节奏一致
  • 卡片式信息组织，模块化展示复杂内容
  • 克制的动效，只在关键交互处使用
Outcome / Reflection

更容易理解，也更容易信任

SYNX 把复杂技术内容重新组织成一条更清晰的企业决策路径。

价值优先的信息架构

用户先理解"为什么"，再深入了解"怎么做"。

多页面各司其职

Home / Docs / About / Blog 形成完整的说服链条。

视觉建立专业信任

深蓝科技调性让复杂产品显得可靠而非 intimidating。

决策路径更短

从了解产品到联系销售，每一步都有明确的信息支撑。

"技术产品的官网，不是技术说明书，而是信任的起点。"
SYNX 的设计不是展示所有功能，而是帮助用户做出"值得继续了解"的判断。
当信息有层次、有节奏地呈现时，复杂本身就不再是障碍。
